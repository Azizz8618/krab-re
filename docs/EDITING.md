# Директивы редактирования — проверено на живой машине

Наблюдения сняты на работающей системе (версия КРАБ 19 от 27.11.92) под
номером 1234. Состояние файла наблюдается директивой `ДЛИ`, выдающей
`<КАРТ> <СЛОВ> <УКАРТ>` — например `0003  0012  0013` для файла из трёх
строк.

## Форматы и эффект

| Директива | Формат | Наблюдаемый эффект |
| --- | --- | --- |
| `ИМЯ` | `ИМЯ <НАЗВАН> [<ХОЗЯИН>]`, имя — **не более 6 знаков**, первая — буква | ответ `НЕТ В КАТАЛОГЕ` (файла нет) либо `ФАЙЛ СО СБОЙНЫХ ЗОН` (файл остался на рабочих зонах); при переполненных зонах — `НЕТ ЗОН ДЛЯ УПРАТ` |
| `ДОП` | `ДОП`, далее строки под приглашением `+`, пустая посылка — конец | текст добавляется в начало файла |
| `ВЫД` | `ВЫД [<ДИАПАЗОН>]` | карты с номерами: `0001 ЯНВАРЬ` |
| `УПЛ` | `УПЛ` | уплотнение, длина меняется |
| `ДБЛ` | `ДБЛ <Н1> <Н2> <Н3>` — параметры через **пробел** | копии строк `Н1…Н2` вставляются перед строкой `Н3`, оригинал сохраняется: 4 карты → 5 (проверено) |
| `СДВ` | `СДВ <Н1> <Н2> <Н3>` — параметры через **пробел** | то же, но оригинал не сохраняется: число карт то же (4 → 4) |
| `СКЛ` | `СКЛ <N1> <N2>` — параметры через **пробел** | склейка карт, у склеиваемых уничтожаются признаки конца карт: 3 карты → 2 |
| `УПС` | `УПС <СИМВОЛ>` | символ конца строки меняется без диагностики; прежняя разметка карт после этого не сохраняется |
| `РЕД` | `РЕД` — **без параметров** | вход в комплексный редактор, приглашение `/`; протокол — ниже |
| `ЗАП` | `ЗАП <НАЗВАН> [<ХОЗЯИН>]` | приглашение `ПАРОЛЬ`; пустая посылка — без пароля. У гостя ответ `НЕТ МЕСТА В АРХИВЕ` |
| `ФОР` | `ФОР [<РЕЖИМЫ>] [:<ФАЙЛЫ>]` | на несформированный файл — `ОШИБКА В ПАСПОРТЕ`; при занятой ПЗ — `УЖЕ ЕСТЬ ПЗ` |
| `КЗМ` | `КЗМ <РАЗД><КТ><РАЗД><РТ>[<Н1>[-<Н2>]]` | контекстная замена; разделитель по умолчанию — точка; при неверном разделителе — `ОШ В ДИР` |

## РЕД: правка нескольких строк через автономный режим

Форма обращения — `Р[ЕД]`, **без параметров**: номера правящихся строк
передаются в самих строках, в первых четырёх позициях. Описание взято из
Школы (`ШКО РЕД`, библиотечный файл `SCU101`) и проверено на живой машине.

Порядок работы:

1. выдать на экран строки, которые правятся, директивой `ВЫД` — номера
   карт должны быть видны и не искажены выводом;
2. набрать `РЕД` и дождаться приглашения `/`;
3. **перевести терминал в автономный режим** (OFFLINE; на 15ИЭ — клавиша
   `РЕЖИМ`/`F9`, «АВТОНОМНО»): машина перестаёт обновлять экран, и
   пользователь правит показанные строки сам;
4. набирать исправленные строки с номерами в первых четырёх позициях:
   все, кроме последней, завершаются `LINE FEED` (0x0A), последняя —
   символом `ETX` (0x03);
5. поставить курсор на первую изменённую строку и нажать `SEND`
   (`ПЕРЕДАЧА`/`F10`).

Номера исправляемых строк **не обязаны идти подряд** — так и проверено:
`РЕД` с парами 1 и 3 меняет их, вторую не трогает.

В эмуляторе 15ИЭ (`ie15emu`) накопленный набор отдаётся целиком, поэтому
позиционировать курсор по экрану не нужно — достаточно правильных
номеров в начале строк. Соответствующий вызов драйвера:
`KrabSession.red_edit({1: "январь", 3: "ноябрь"})`.

Ввод в Н2: регистр не важен — набор Н2 приводит и строчные, и заглавные
русские к одному коду ЭВМ (однорегистровость строки). Раньше заглавные
ошибочно уходили латиницей позиции (`key_to_bytes` в Н2 менял алфавит по
Shift) — «ДЕКАБРЬ» в файл попадал как «LTRF,HM», мусор; это исправлено в
эмуляторе ie15. Набирать можно любым регистром; КРАБ по-прежнему приводит
текст к верхнему регистру при выводе.

Формат `КЗМ` указан в Школе (`ШКО КЗМ`, `SCU105`) явно:

    КЗ[М] <РАЗД><ОБРАЗЕЦ><РАЗД><ЗАМЕНА>[<НАЧСТР>[<КОНСТР>]]
    <РАЗД> — символ, НЕ ВСТРЕЧАЮЩИЙСЯ в наборах <ОБРАЗЕЦ> и <ЗАМЕНА>

то есть разделитель — любой знак, которого нет в самом тексте замены. На
этой машине разделителем по умолчанию служит **точка**, поэтому запись
имеет вид

    КЗМ .<КОНТЕКСТ>.<ЗАМЕНА>.<Н1>[-<Н2>]

например `КЗМ .янв.май.1-3`. Диапазон строк необязателен — без него замена
идёт по всему файлу. Отказ при неверном разделителе (`ОШ В ДИР`) проверен
на живой машине.

Замена идёт **по вхождению**: `КЗМ .янв.май.1-3` на файле
`январь/февраль/март` даёт `майарь` в первой строке (в «январь» входит
«янв», «арь» остаётся) и отчёт `ЗАМЕН 000001 ШТ.` — замен ровно одна,
потому что «янв» больше нигде не встречается.

Директивы `РЗД` в этой версии системы **нет**: `РЗД .` отвечает
`НЕТ ДИРЕК`. В корпусе текстов 1978—1993 гг. она тоже не значится — в
указателе директив Школы её нет, встречаются только внутренние метки
`НАЙРЗД` в БСС. Значит разделитель задаётся генератором при настройке
системы, и автотестам остаётся закладывать точку: сменить его на этой
машине нечем.

## Особенности состояния, важные для тестов

Это свойства самой системы, а не дефекты тестов — их нужно учитывать при
любой автоматизации:

1. **Файлы сбойных зон переживают сеанс.** Директива `ИМЯ` с постоянным
   именем поднимает накопленный файл, и содержимое растёт от прогона к
   прогону. Для автотестов имя файла должно быть уникальным на каждый тест.
2. **У номера одна подчинённая задача.** Занятая ПЗ меняет ответ `ФОР`
   на `УЖЕ ЕСТЬ ПЗ` и ломает последующий `ЛИС` (`НЕТ ПЗ В РЕШЕНИИ`).
3. **У гостя нет места в архиве.** `ЗАП` завершается `НЕТ МЕСТА В
   АРХИВЕ`, поэтому проверки записи в архив для номера 1234 невозможны —
   нужен номер с бюджетом.
4. **Файлы сбойных зон удаляются не сразу.** Срок хранения задаётся
   генератором (1–4 суток). Администратор может очистить их разом через
   `АДМ ЧИС СБЗ`, но rights администратора не нужны: файл освобождается
   и обычной последовательностью **ИМЯ + КОН** (проверено — файл уходит
   из списка `СБО`).
5. **Директива `ВЫХ` в Мониторе не работает** — отвечает `НЕТ ДИРЕК`;
   она относится к программе Лист. Для освобождения файла используется
   именно `КОН`.
6. **СБО работает по шифру, а не по терминалу.** По `ШКО105` директива
   имеет вид `СБ[О] <ШИФР>` и выдаёт имена файлов на сбойных зонах
   **для пользователя, чей шифр указан**. Без параметра выдаётся список
   текущего номера. В выдаче видны: имя файла, шифр хозяина, комплект
   зон (`Б-3`) и номер терминала (`Т-NN`).

7. **ИМЯ ищет файл сначала на сбойных зонах, потом в архиве**
   (`ШКО101`): «если файла нет на сбойных зонах, но в архиве есть —
   текущий файл считывается из архива КРАБ, иначе „НЕТ В КАТАЛОГЕ“».
   Ограничения по номеру терминала в описании директивы **нет**.

## Освобождение сбойных зон — что сказано в текстах

Срок хранения задаётся Генератором (поля Е1—Е3, 1—4 суток) и хранится в
параметре `ВРСБЗ`, который читает программа Лист:

```
ВРСБЗ   1- 3 РР  срок хранения файлов на сбойных зонах в днях
       4-19 РР  двузначный номер диска сбойных зон
      20-34 РР  количество комплектов СБЗ (в обратном коде минус одна)
      37-48 РР  начало СБЗ для Листа в каталоге
```

**Освобождение старых комплектов автоматическое.** При загрузке программа
Лист выполняет `ЗХСБС «ПОИСК СТАРЫХ СБОЙНЫХ ЗОН»`, сверяет текущую дату с
`ВРСБЗ` и вызывает `ОСВОБ «ОСВОБОЖДЕНИЕ СТАРЫХ КОМПЛЕКТОВ»»; если
комплектов нет — выдаёт `Э50 '116' ОСВОБОЖДЕНИЕ ДИСКА`, то есть файлы
с истёкшим сроком хранения снимаются без участия администратора.

Дополнительно в системе есть:

- служебная задача **ФСБН** — проверка состояния сбойных зон
  («ФАЙЛОВ НА СБОЙНЫХ ЗОНАХ НЕТ», «ОТКАЗ ОТ ДИСКА СБОЙНЫХ ЗОН»);
- директива **СОХ** — сохранить текущий файл на сбойных зонах под новым
  именем;
- административная очистка `АДМ ЧИС СБЗ` — разово и сразу;
- директива `КОН` — по `ШКО101`, при завершении работы в номере файл на
  сбойных зонах «пропадает».

Практический вывод: файлы уходят с сбойных зон либо сами по истечении
срока хранения (достаточно обращения к программе Лист), либо при `КОН`,
либо через `ФСБН`/`АДМ ЧИС СБЗ`. Номера терминалов в выдаче `СБО`
(`Т-02`, `Т-17`, `Т-20`) — сведения о том, каким терминалом файл создан;
согласно описанию `ИМЯ` ограничения по терминалу в поиске файла нет.

## Ручная очистка (историческая заметка)

Файлы на сбойных зонах держат комплекты зон до истечения срока хранения
(1–4 суток). Очистить их можно без прав администратора системы:

```
СБО                    — посмотреть, что осталось
ИМЯ <ИМЯ ФАЙЛА>        — поднять файл на рабочее поле
КОН                    — завершить сеанс; файл с СБЗ пропадает
СБО                    — проверить, что файл исчез из списка
```

Вариант для разового запуска — [`tools/clear_sbo.py`](../tools/clear_sbo.py):
он сам входит в номер, перебирает список и повторяет цикл, пока список не
опустеет.

Проверено на живой машине: файл `КАЛЬК`, поднятый директивой `ИМЯ` и
закрытый `КОН`, исчез из выдачи `СБО`, число файлов уменьшилось с 8 до 7.

Ограничения автоматизации (проверено на живой линии ДКС):

- после `КОН` и `КОНЕЦ СЕАНСА` старая линия перестаёт принимать ввод —
  КРАБ на ней не запускается, нужно переподключение на другую линию;
- часть линий искажает символы при наборе сразу после входа; драйвер
  сверяет эхо с набранным и повторяет посылку при расхождении;
- часть символов машина отдаёт в кодах, которые терминал показывает
  латиницей (`RFКМR` вместо `КАЛЬК`); на приём директив это не влияет —
  система отвечает верно, — но такой файл уже нельзя адресовать по имени.

Вывод: очистку сбойных зон надёжнее делать вручную, по одному файлу за
сеанс, а автоматизацию считать вспомогательной.

## Рекомендации по расширению тестов

- проверять инварианты числа карт по `ДЛИ`, а не конкретный текст файла;
- перед каждым формированием дожидаться освобождения ПЗ или сбрасывать
  её директивой `ВЫБ`;
- не полагаться на ответ `ОШИБКА В ПАСПОРТЕ` как на единственный исход
  `ФОР` — при занятой ПЗ приходит `УЖЕ ЕСТЬ ПЗ`;
- уникальные имена файлов на каждый тест, иначе содержимое на сбойных
  зонах будет копиться.
