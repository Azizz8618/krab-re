# Директива ФОР — все форматы команды формирования задач

Документ собран по текстам системы КРАБ: школьному описанию `ШКО101`
(файл `texts/SCU101`), разбору параметров в Мониторе абонентов
(`texts/FNC1`), структуре списка файлов (`texts/F12`) и модулю
формирователя (`texts/FFOR`).

## 1. Каноническая форма

```
Ф[ОР] [ [<Р1>] [<Р2>] … ]  [ : <И1> … <ИN> ]
```

Разделы команды:

| Раздел | Назначение |
| --- | --- |
| `<РN>` | режимы формирования; сколько угодно, порядок произвольный |
| `:` | разделитель перед списком формируемых файлов |
| `<ИN>` | имена формируемых файлов с указанием расположения и хозяев |

`<РЕЖИМ ФОРМИРОВАНИЯ> ::= <СИСТЕМА ПРОГРАММИРОВАНИЯ> I
                         <РЕЖИМ РАБОТЫ ЗАДАЧИ> I
                         <СЕРВИСНЫЕ РЕЖИМЫ>`

То есть режим набирается **буквами из трёх групп** — можно указать только
одну группу (например `ФОР ПЗ`) или все три (`ФОР МС ПЗ ПАС 2`).

Если параметры опущены совсем, формируется **текущий файл**.

Справка по группам выдаётся на терминал:

```
ШКО ФОР СПР   — системы программирования
ШКО ФОР РЕЖ   — режимы работы задачи
ШКО ФОР СЕР   — сервисные режимы
```

## 2. Группа 1 — система программирования (`ШКО ФОР СПР`)

| Режим | Назначение |
| --- | --- |
| `МС` | задачи мониторной системы «Дубна» и задачи БЭСМ-алгол |
| `БЕМ` | задачи на автокоде БЕМШ |
| `КОД` | задачи в кодах машины |

По умолчанию действует `МС` (если группа не указана).

## 3. Группа 2 — режим работы задачи (`ШКО ФОР РЕЖ`)

| Режим | Назначение |
| --- | --- |
| `ТЕЛ` | задача на буфер ввода ОС ДИСПАК; **в паспорт вставляется раздел `ТЕЛЕ^`** |
| `ПЗ` | подчинённая задача; выдаётся уведомление об окончании задачи |
| `ПАК` | «отладочная» задача в пакет ОС ДИСПАК с выдачей результатов на АЦПУ БЭСМ-6 |
| `ПС` | подсистема КРАБ — однотерминальная подчинённая задача |
| `СЧЕ` | «счётная» задача в пакет; оператору на операторский терминал выдаётся сообщение |
| `ИНК` | «отладочная» задача в пакет **без** выдачи на АЦПУ |
| `ЛИС` | «отладочная» задача; результаты пишутся в файлы `АЦПУ01`, `АЦПУ02`, …; только для мониторной системы «Дубна» |
| `КАН` | задачи с использованием аппарата «КАНАЛ» |
| `БУФ` | задачи на буфер ввода **системы КРАБ** (не ОС ДИСПАК) |

Отличие `ПЗ` и `ПС` видно и на живой машине: `ФОР ПЗ` после постановки
задачи включает подсистему и спрашивает `ПОДСИСТЕМА ВКЛЮЧЕНА /
ВОЙТИ? (ДА,НЕТ)`, а `ФОР ПС` запускает однотерминальную подсистему —
диалоговую задачу (например с паспортом, содержащим `ТЕЛЕ^`).

Просмотр результата возможен только для подчинённых задач — `ПЗ` или `ПС`;
программа ЛИСТ перехватывает выдачу такой задачи.

## 4. Группа 3 — сервисные режимы (`ШКО ФОР СЕР`)

| Режим | Назначение |
| --- | --- |
| `VT` | полная аварийная выдача при **нормальном** окончании подчинённой задачи |
| `ПАС NN` | замена стандартного паспорта задачи паспортом с номером `NN` |

Номера стандартных паспортов хранятся в поле `NСТПАС` (16 разрядов) —
это те же номера, что указываются в карточке паспорта.

## 5. Список формируемых файлов

```
<ИN> ::= <ИМЯ ФОРМИРУЕМЫХ ФАЙЛОВ С УКАЗАНИЕМ МЕСТОРАСПОЛОЖЕНИЯ И ХОЗЯЕВ>
```

Элемент списка разбирается в пять полей (структура `ФОБЛ`, `F12`):

| Поле | Содержимое |
| --- | --- |
| `ФОБЛ+1` | имя массива |
| `ФОБЛ+2` | хозяин массива |
| `ФОБЛ+3` | пароль массива |
| `ФОБЛ+4` | номер архива **или** имя библиотеки |
| `ФОБЛ+5` | хозяин библиотеки |

Область `ФОБЛ` занимает 15 слов: 6 слов — заголовок (номер терминала и
адрес следующей области), далее до 6 файлов по 5 слов (`ДЛФОБЛ = 6`).
Список — цепочка таких областей.

Указание расположения в директиве (по руководству):

| Запись | Смысл |
| --- | --- |
| `/<НОМАРХ>` | часть общего архива |
| `=<НОМБОБ><СДВИГ>` | номер ленты или диска личной библиотеки |
| `<ИМЯБИБ><ХОЗБИБ>` | именованная библиотека и её хозяин |

Признак «массив из общего архива / из библиотеки» различает сам
формирователь (`FFOR`):

| Разряд | Значение |
| --- | --- |
| 30-й разряд `РАБПОЛ+1` | `0` — массив из общего архива, `1` — из библиотеки |
| 33–36 разряды | тип библиотеки |
| 37–48 разряды | начало библиотеки |
| `РАБПОЛ+2`, 1–48 | имя библиотеки |
| `РАБПОЛ+2`, 1–16 | номер бобин(ы) библиотеки |
| `РАБПОЛ+2`, 1–7 | номер архива |

Имена вида `>>АРХН`, `>>ТЕКС`, `>>ПОСТ`, `>>ТРМЛ` — группы файлов общего
архива (перечень групп виден в каталоге, например в `PP1`).

## 6. Итоговые варианты команды

| Команда | Что формируется |
| --- | --- |
| `ФОР` | текущий файл, режимы по умолчанию |
| `ФОР ПЗ` | подчинённая задача из текущего файла |
| `ФОР ПАК` | отладочная задача в пакет с выдачей на АЦПУ |
| `ФОР ИНК` | то же без выдачи на АЦПУ |
| `ФОР СЧЕ` | счётная задача (с уведомлением оператору) |
| `ФОР ТЕЛ` | задача с разделом `ТЕЛЕ^` в паспорте |
| `ФОР ПС` | подсистема — диалоговая однотерминальная задача |
| `ФОР ЛИС` | задача с записью результата в файлы `АЦПУ01`, `АЦПУ02` |
| `ФОР БУФ` | задача на буфер ввода самой системы КРАБ |
| `ФОР КАН` | задача с аппаратом «КАНАЛ» |
| `ФОР МС` | текст в мониторной системе «Дубна» / БЭСМ-алгол |
| `ФОР БЕМ` | текст на автокоде БЕМШ |
| `ФОР КОД` | текст в кодах машины |
| `ФОР ПЗ ПАС 3` | подчинённая задача с заменой стандартного паспорта №3 |
| `ФОР ПЗ VT` | подчинённая задача с аварийной выдачей при нормальном окончании |
| `ФОР МС ПАК:ИМЯ1,ИМЯ2` | два файла из архива в одной задаче |
| `ФОР ПЗ:ИМЯ ХОЗ` | файл заданного пользователя |
| `ФОР ПС:ИМЯ/2` | файл части архива №2 |
| `ФОР ПЗ:ИМЯ=2063` | файл личной библиотеки на бобине 2063 |

## 7. Сетевой вариант: ФОРМ — формирование на другой машине НЕРПА

Отдельная ветвь в Мониторе (`FNC1`, метка `ФОРМ` — «формирование задачи
на другую машину сети НЕРПА»). Разбор параметров ведётся теми же тремя
вопросами (запрос номера, запрос ключа, разбор ключа), но состав полей иной:

| Шаг | Поле | Назначение |
| --- | --- | --- |
| 1 | `ФРИМЯ` | имя массива; ошибка — `ИМЯ НЕ ИНДЕНТИФИКАТОР` |
| 2 | `ФРТВ` | тип вывода или кодировка; без параметра — `ТИП ВЫВОДА НЕ ЗАДАН` |
| 3 | `ФРДАТ` | дата последнего изменения файла |
| 4 | `ФРПАР` | пароль на шифр формирующей машины; без него — `НЕТ ПАРОЛЯ НА ШИФР` |
| 5 | `ФРВЫВ` | признак выдачи (`Е2`) |
| 6 | `ФРШИФ` | шифр (0 — временно) |
| 7 | `ФРПАС` | номер стандартного паспорта (`СТПАС`) |
| 8 | `ФРЛИС` | признак записи листинга (`Е27`) |
| 9 | `ФРКОД` | код (`Е26`) |
| 10 | `ФРСТП` | признак `Е1` |
| 11 | `ФРКОН` | канал и адрес назначения в сети |

Признак признаков директивы (`ПРИЗНД = Е42`) на этой ветви обязателен.

## 8. Диагностики формирования

Из `texts/SCU108` и модулей:

| Сообщение | Причина |
| --- | --- |
| `ДРУГОЙ ШИФР` | формирование под недоступным шифром |
| `МНОГО ИМЕН` | в директиве более 8 имён файлов из архива |
| `НЕВЕРНЫЙ ПАРОЛЬ НА ШИФР` | неверно задан пароль на шифр формирования |
| `СЛИШКОМ МНОГО ЗАДАЧ` | на буфере ввода больше задач, чем разрешено администратором |
| `МНОГО ЗАДАЧ ЗА СЕАНС` | сформировано 37 задач за один сеанс |
| `ФОРМИРОВАНИЕ ЗАПРЕЩЕНО` | оператор ЭВМ запретил формирование |
| `ОТЛАДОЧНЫЕ ЗАДАЧИ ЗАПР` | запрещены отладочные задачи (`ПАК`, `ИНК`, `ЛИС`) |
| `СЧЕТНЫЕ ЗАДАЧИ ЗАПР` | запрещены счётные задачи |
| `ПОДЧИНЕННЫЕ ЗАДАЧИ ЗАПР` | запрещены подчинённые задачи (`ПЗ`, `ПС`) |
| `НЕТ МЕСТА ДЛЯ ЗАДАЧИ` | в каталоге ввода ОС ДИСПАК нет места |
| `ЕСТЬ ЗАДАЧА С ШИФРОМ` | на буфере уже есть задача с тем же шифром |
| `ОШИБКА В ПАСПОРТЕ` | текст задачи не является паспортом |
| `НЕТ СВОБОДНЫХ ЗОН НА БУФЕРЕ` | нет места на буфере ввода |
| `БУФЕР ВВОДА ПЕРЕПОЛНЕН` | переполнен буфер ввода ОС ДИСПАК |
| `ДЛИННЫЙ ПАСПОРТ` | длина паспорта больше 512 символов |
| `НЕ ИМЕЕТЕ ПРАВА` | запрет по правам |

Дополнительное ограничение, подтверждённое на живой машине: у номера может
быть **только одна подчинённая задача**. При занятой ПЗ повторное
`ФОР ПЗ` отвечает `УЖЕ ЕСТЬ ПЗ`, а `ЛИС` — `НЕТ ПЗ В РЕШЕНИИ`.

## 9. Проверено на живой машине

| Команда | Ответ системы |
| --- | --- |
| `имя форгдр` | `ИМЯ ФОРГДР` |
| `фор пз` | `ШИФР 123400000000`, затем `ПОДСИСТЕМА ВКЛЮЧЕНА / ВОЙТИ? (ДА,НЕТ)` |
| `да` | `ВНИМАНИЕ! ОКОНЧИЛАСЬ ЗАДАЧА ШИФР 123400000000` |
| `лис` | `** К Р А Б ** (ЛИСТ*ВЕР.19/1 ОТ 04.06.92)` — вход в программу Лист |
| `дли` (в Листе) | `ЗТРАК =015  ИТРАК =094`, `00005 - КОНЕЦ БУФЕРА` |
| `выд` (в Листе) | листинг задачи |
| `кон` (в Листе) | возврат в Монитор абонентов |

Для диалоговой задачи (`КАЛЬК`, Паскаль, в паспорте `ТЕЛЕ^`) применяется
`ФОР ПС` — так задача становится подсистемой, с которой работает Монитор.
